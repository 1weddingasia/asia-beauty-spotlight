# Project Review Summary

### Top Issues

1. **Broken/absent authorization on admin surfaces (highest severity).** Admin privilege is derived from `user_metadata.role`, which users can write themselves, and the gate is a denylist rather than an allowlist.
   - `src/app/(admin)/layout.tsx` allows any role except `owner` (including `undefined`).
   - `src/utils/supabase/middleware.ts` trusts `user.user_metadata?.role` for `/admin` gating.
   - `src/app/api/admin/users/route.ts` exposes `auth.admin.createUser`/`deleteUser` with **no caller auth check at all**, and even ships a **hardcoded real `service_role` JWT fallback** committed to the repo.
   - Multiple admin pages (`categories`, `plans`, `locations`) perform privileged mutations directly from the browser with no role check, relying entirely on RLS.

2. **Stored XSS via AI/user-authored HTML rendered with `dangerouslySetInnerHTML`.** Unsanitized HTML flows end-to-end with no sanitization at any boundary.
   - `src/app/api/ai/write-blog/route.ts` returns model-generated HTML; `src/app/blog/[slug]/page.tsx` renders it raw (prompt-injectable via user `prompt`).
   - `src/app/(admin)/admin/businesses/[id]/BusinessEditorClient.tsx` and `src/app/(business)/dashboard/profile/page.tsx` render `pageContent.map_embed` raw (map-embed textarea).
   - `src/components/site/BusinessCard.tsx` / `BusinessEditorClient` accept arbitrary business HTML.

3. **Webhook forgery and non-idempotent VIP upgrade.** `src/app/api/webhooks/sepay/route.ts` skips signature verification entirely when the secret or signature header is absent, uses `!==` (non-constant-time) comparison, fails to anchor VIP memo parsing, and re-applies upgrades on retry (only the initial insert is unique-guarded). This is a payment-integrity failure.

4. **Open redirects derived from untrusted input.**
   - `src/app/auth/callback/route.ts` concatenates an unvalidated `next` param into the redirect target (`//evil.com`, `/\evil.com`).
   - `src/app/auth/signout/route.ts` derives the redirect origin from a spoofable `Host`/`X-Forwarded-Host` header.

5. **Pervasive silent error swallowing** — the single most repeated root cause across the repo. Supabase `error` is discarded and replaced with a misleading empty/fallback state on both server and client, hiding outages and RLS failures.
   - Server: `src/app/actions/search.ts`, `src/app/(admin)/admin/{blogs,businesses,users,settings}/page.tsx`, `src/app/blog/page.tsx`, `src/app/bang-gia/page.tsx`, `src/app/danh-muc/[slug]/page.tsx`, `src/app/uu-dai/page.tsx`.
   - Client: `src/app/lien-he/ContactPageClient.tsx`, `src/app/(business)/dashboard/page.tsx`.
   - A variant, false success, is worse: `src/app/actions/contact.ts` returns `{ success: true }` even when the insert fails, and the UI tells the user their request was "received".
   - And "not found" is fabricated from errors: `src/app/(admin)/admin/businesses/[id]/page.tsx` calls `notFound()` on a DB failure.

6. **`any` used pervasively, defeating type safety on the data-shaping path.** ~20+ files use `any` for state, props, and caught errors despite a project rule against it (see below). This directly enables several runtime crashes. Representative: `src/data/business.ts`, `src/types/business.ts`, `src/app/page.tsx`, `src/components/site/BusinessCard.tsx`, `src/app/doanh-nghiep/[slug]/BusinessPageClient.tsx`.

7. **Date parsing is unsafe and inconsistent everywhere offers/hours are handled.** Malformed/`null` dates become `Invalid Date` or epoch (1970), and comparison operators on `Invalid Date` are always `false`, so filtering silently fails.
   - `src/app/uu-dai/page.tsx`, `src/app/page.tsx`, `src/app/doanh-nghiep/[slug]/BusinessPageClient.tsx` (with divergent `includes('-')` vs `includes('/')` format detection), `src/app/blog/page.tsx`, `src/app/blog/[slug]/page.tsx`.

8. **Env/config handling: no fail-fast, only placeholders or crashes.**
   - `src/utils/supabase/{client,server,middleware}.ts` use `!` non-null assertions or silently fall back to a placeholder URL (`https://placeholder.supabase.co`).
   - `src/app/layout.tsx` runs `new URL(SITE_URL)` at module load → crashes the whole app on a malformed env value, and leaks the raw env into `canonical`.
   - `src/app/api/ai/write-blog/route.ts` sends `Bearer undefined` to third parties when keys are unset.

9. **Duplicate DB round trips per request.** `generateMetadata` and the page body each re-fetch without `cache()`: `src/app/blog/[slug]/page.tsx`, `src/app/doanh-nghiep/[slug]/page.tsx`, `src/app/danh-muc/[slug]/page.tsx`. Combined with `select('*')` everywhere and no pagination/limit on admin lists, this is a systematic performance and data-exposure issue.

10. **Hardcoded business URLs, routes, roles, and secrets scattered across the codebase**, directly violating the stated no-hardcoding rule. Route literals duplicated (`/login`, `/dashboard`, `/admin`), Unsplash/Pexels URLs inlined in styles and components, payment constants (bank account, amount, QR URL) embedded in the client bundle (`src/app/(business)/dashboard/upgrade/page.tsx`), and role strings inconsistent (`'admin'/'superadmin'` in `login/page.tsx` vs `'owner'` in middleware).

### Module Hotspots

- **`src/app/(admin)/admin/**`** — by far the densest area. Nearly every page repeats the same cluster: ignored `error`, `select('*')` without limit, `any` typing, nested ternaries, no in-flight guards on destructive actions (`BlogsClient.tsx`, `BusinessesClient.tsx`, `locations/page.tsx`, `plans/page.tsx`, `categories/page.tsx`), and client-side privileged mutations.
- **`src/utils/supabase/**`** — small but security-critical; all three files have credential/validation problems that amplify every other finding.
- **`src/app/actions/*` and `src/app/api/**`** — silent swallowing and auth issues concentrated here (`contact.ts` false success, `search.ts` wildcard injection, `webhooks/sepay` forgery, `admin/users` no-auth).
- **`src/app/(business)/dashboard/**`** — state mutation, `any`, hardcoded payment data, missing cleanup timers.
- **`src/app/doanh-nghiep/[slug]/` and `src/app/page.tsx`** — heaviest `any` usage plus the offer-date bugs.

### Cross-Cutting Concerns

- **No input validation on the mutation path.** `category`/`location` passed raw into `.eq()` (`src/app/actions/search.ts`), LIKE wildcards not escaped (full-table-scan via `q=%`), `parseInt(price)` inserted unvalidated (`PlansClient.tsx`), wholesale raw `page_content` object written to a JSON column (`import/page.tsx`), unrestricted `as string` casts on `FormData` values (`contact.ts`).
- **Non-idempotent / unguarded destructive and create operations.** Double-click deletes fire concurrent requests across every admin client; the webhook upgrade is not retry-safe.
- **No in-flight guards and no mounted/cleanup guards.** Rapid clicks and post-unmount `setState` recur in `upgrade/page.tsx`, `login/page.tsx`, `BackToTop.tsx`, `BusinessesClient.tsx`, `BlogsClient.tsx`, `locations/page.tsx`.
- **Duplicate business logic that will drift.** Relation-flattening logic duplicated across `src/data/business.ts`; plan/pricing logic inlined in view (`PricingClient.tsx`, `dashboard/layout.tsx`); route and role constants repeated instead of centralized; `fetch` helpers across admin pages.
- **Hardcoded external asset URLs and inline styles.** Unsplash/Pexels URLs in `src/app/tim-kiem/page.tsx`, `src/app/lien-he/ContactPageClient.tsx`, `src/app/blog/page.tsx`, `src/components/site/BusinessCard.tsx`, `src/app/danh-muc/[slug]/page.tsx`.
- **Non-constant-time or missing signature/scheme checks** on security-sensitive comparisons (`webhooks/sepay`) and `href` values lacking protocol allow-listing (`BusinessPageClient.tsx`: `javascript:` injectable).
- **Accessibility gaps.** No live-region on error page (`src/app/error.tsx`), content headlines used as image `alt` (`HeroSlider.tsx`), missing `autoComplete`/`name`/password `type` on login and user-creation forms, unlabeled submit controls (`SearchBar.tsx`).
- **Empty/no-op catch blocks and unused caught `err` bindings** repeated across `ContactPageClient.tsx`, `categories/page.tsx`, `plans/page.tsx`, `UsersClient.tsx`, `profile/page.tsx` — always degrading diagnosis quality.

### Quick Wins

- **Add `if (!error) ... else surface/log`** to the Supabase reads across admin pages and the blog/offers/category pages. This single change converts a large share of the "silent empty state" and "page shows nothing" findings into diagnosable behavior.
- **Import the missing `useEffect` and replace the misused `useState(initializerFn)` fetch** in `src/app/(admin)/admin/blogs/[id]/page.tsx` — the page currently never fetches data.
- **Wrap awaited mutations in `try/catch/finally`** and reset the relevant loading flag: `login/page.tsx` (currently disables the button permanently), `upgrade/page.tsx` (`setChecking(false)` unreachable), and each `handleDelete`.
- **Add `.filter(Boolean)`** and extract the shared relation-flattening helper in `src/data/business.ts` (fixes the `undefined`-entries bug in `getBusinessBySlug`); delete the dead `selectStr`.
- **Mechanical cleanups:** remove the committed `service_role` JWT from `src/app/api/admin/users/route.ts` (rotate it immediately), replace `!==` with `crypto.timingSafeEqual` in `webhooks/sepay/route.ts`, remove unused imports/dead code (`ArrowLeft` in `dashboard/layout.tsx`, `isYearly` in `PricingClient.tsx`), delete unused/dead modules `src/lib/search.ts`.
- **Guard primitive render sites:** `business?.slug?.toUpperCase()`, `b.name?.[0] ?? '?'`, `price_monthly != null`, and null checks before `new Date(...)` formatting — small edits that remove several guaranteed `TypeError`/`Invalid Date` crashes.
- **Add `encodeURIComponent`/`URLSearchParams`** to the keyword→Pexels query and the `userId` query string in `UsersClient.tsx`.
- **Deduplicate fetches with React `cache()`** in `blog/[slug]`, `doanh-nghiep/[slug]`, and `danh-muc/[slug]` to halve DB round trips per request.
